# แนวทาง Smart-Asset สำหรับงานราชการ

ใช้โครงสร้าง GovAsset เดิม (Python, SQLite และหน้า HTML/CSS/JavaScript) ITAM เป็น reference เฉพาะพฤติกรรมที่มีประโยชน์ เช่น QR คงที่ ประวัติการซ่อม checklist และงานตามรอบ ไม่ยก framework, schema หรือขั้นตอนธุรกิจเอกชนมาทั้งชุด

- **ทะเบียนครุภัณฑ์:** เลขครุภัณฑ์ FSN วิธีได้มา แหล่งเงิน GFMIS/PO สถานที่ หน่วยงานรับผิดชอบ และหลักฐานต้นทาง ต้องตรวจย้อนกลับได้ ไม่จับคู่ระเบียนจากชื่ออย่างเดียว
- **PM และตรวจนับ:** ตั้งรอบวัน/สัปดาห์/เดือน/ทุก N หน่วย มอบหมายผู้ตรวจ/ช่าง ระบุผลตรวจและวันที่จริง หากพบชำรุดให้เชื่อมคำร้องซ่อมกับครุภัณฑ์และงานตรวจเดิม
- **คำร้องซ่อม:** ผู้แจ้ง → เจ้าหน้าที่พัสดุ → ผู้อนุมัติตามเกณฑ์หน่วยงาน → ช่างดำเนินงาน → ตรวจรับ/ยืนยันผล เก็บประวัติและค่าใช้จ่ายเป็นหลักฐาน งบอนุมัติต้องตั้งตามระเบียบของหน่วยงาน ไม่ถือค่าตัวอย่างเป็นระเบียบกลาง
- **เอกสาร:** ใบคุมทรัพย์สินยึด PDF ที่ผู้ใช้ให้ A4 แนวนอน 12 คอลัมน์ ฟอนต์ในแอป และข้อมูลฉบับเอกสารแยกจากทะเบียน ห้ามเพิ่มโลโก้หรือเครดิตผู้พัฒนาลงในพื้นที่แบบฟอร์มราชการ อัตราค่าเสื่อมและตัวเลขที่ไม่มีหลักฐานต้องตรวจ/กรอก ไม่สมมติค่าแทน
- **QR:** ป้ายใช้ URL/token คงที่ อ่านข้อมูลล่าสุดจากทะเบียนและเปิดแจ้งซ่อมได้ ข้อมูลภายในและข้อมูลผู้แจ้งต้องไม่แสดงในหน้าติดตามสาธารณะ
- **อัตลักษณ์:** ชื่อ/โลโก้ปรับตามหน่วยงาน เครดิตผู้พัฒนาเป็น `POWER BY PNG TEAM` สีส้ม `#f97316` ในจุดที่แสดงเครดิต

ต้นแบบยังใช้บทบาทจำลอง การอนุมัติในหน้าจอจึงเป็นการทดสอบ workflow ไม่ใช่การลงนามหรือการรับรองทางราชการ ก่อนใช้ข้อมูลจริงต้องมีระบบยืนยันตัวตน/สิทธิ์ การเก็บหลักฐาน และการสำรองข้อมูลที่ตรวจสอบแล้ว
