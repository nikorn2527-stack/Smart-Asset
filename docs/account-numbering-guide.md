# หน่วยงาน แบบเลขครุภัณฑ์ และหลักเกณฑ์ค่าเสื่อม

เข้า **ตั้งค่า → หน่วยงาน แบบเลข และการผูกค่าเสื่อม** การบันทึกค่าต้องเข้าสู่ระบบและมีสิทธิ์ในองค์กร/สาขาที่เลือก ดู [โครงสร้างปัจจุบัน](shared-equipment-import-access.md)

## 1. หน่วยงานเจ้าของบัญชีและสาขา

PDF เป็นหลักเกณฑ์ร่วมและ RAR/ZIP เป็นทะเบียนจริง การเป็นคนละไฟล์ไม่ใช่เหตุให้แยกระเบียบ ชื่อองค์กรเดิมยังเก็บไว้ แต่เจ้าของทรัพย์สินและสาขาเลือกตอนนำเข้าตามข้อเท็จจริง ไม่เพิ่มทรัพย์สินจริงจากตัวอย่างใน PDF

เพิ่ม/แก้ชื่อและรหัสหน่วยงาน แล้วเพิ่มสาขาภายในหน่วยงานนั้นได้ สาขาที่ใช้กฎเดียวกันไม่ต้องสร้างแบบเลขซ้ำ บัญชีเลขแยกจากข้อความสถานที่ตั้งของอุปกรณ์ และมีตัวกรองบัญชี/สาขาที่หน้าทะเบียน การเปลี่ยนชื่อหรือเพิ่มสาขาไม่เปลี่ยนเลขเดิม

## 2. สร้างแบบเลขจากตัวแปร

ในแท็บ **แบบเลข** เลือกตัวแปรและจำนวนหลัก เรียงด้วยลำดับแถว เพิ่ม/ลบชุดและเลือกตัวคั่นได้ มีตัวอย่างโครงสร้างก่อนบันทึก เช่น:

| แบบ | ความหมาย |
| --- | --- |
| `{group:4}-{type:3}-{detail:4}` | เลขจำแนก 11 หลักตามคำอธิบาย PDF |
| `{group:4}-{type:3}-{detail:4}-{seq:4}` | เลขประจำชิ้น 15 หลักตามรูปแบบหลักใน RAR |
| `{group:4}{detail:4}` | แบบกำหนดเอง 8 หลัก |
| `{group:4}-{type:3}-{seq:3}` | แบบกำหนดเอง 10 หลัก |

จำนวนหลักไม่นับตัวคั่น ตัวเลขสั้นเติมศูนย์ซ้ายได้ แต่ค่าที่ยาวเกินต้องแก้แบบหรือค่าต้นทาง ระบบไม่ตัดหลักทิ้ง รองรับรหัสตัวอักษรที่มีความยาวครบตามกำหนดด้วย

เลือกชนิดเลขให้ถูก:

- **เลขประจำชิ้น:** ห้ามซ้ำในบัญชีหน่วยงานเดียวกัน ไม่จำเป็นต้องมีตัวแปร seq หากตัวแปรอื่นกำหนดเลขเฉพาะชิ้นอยู่แล้ว
- **เลขจำแนกชนิด:** หลายชิ้นมีเลขเดียวกันได้ แต่แต่ละชิ้นมี ID และ QR คนละรายการ ไม่เติมเลขลำดับเอง

เลขลำดับใช้ค่าตัวแปรที่เหลือเป็นขอบเขต และแยกสาขาหรือหมวดเพิ่มได้ เลือกเริ่มรอบปี/เดือนต้องมีตัวแปรปี/เดือนในแบบเลข หากเลขเต็มจำนวนหลักจะหยุดและแจ้งให้กำหนดแบบใหม่ ไม่วนกลับหรือเพิ่มความยาวเอง การดูตัวอย่างไม่กินเลข; ตอนบันทึกจริงจัดสรรภายใต้ transaction และตรวจเลขซ้ำอีกครั้ง หากแบบเลข บัญชีชนิด หรือหลักเกณฑ์เปลี่ยนหลังดูตัวอย่าง ระบบให้ตรวจเลขและหลักเกณฑ์อีกครั้งก่อนบันทึก โดยไม่จองเลขหรือสร้างรายการค้าง

แบบเลขที่บันทึกเป็นฉบับถาวร ใช้ **สร้างรุ่นใหม่จากแบบนี้** เพื่อปรับแบบ แล้วผูกแบบใหม่พร้อมวันเริ่มใช้ การเลือกฉบับใหม่ไม่เปลี่ยนเลขเก่า

## 3. กำหนดแบบตามหมวดและเชื่อมค่าเสื่อม

แท็บ **การใช้แบบเลข / ค่าเสื่อม** เลือกหน่วยงาน สาขาหรือทุกสาขา หมวดหรือทุกหมวด แบบเลข หลักเกณฑ์ค่าเสื่อม และวันเริ่มใช้ เลือกเฉพาะแบบเลขหรือเฉพาะค่าเสื่อมได้

ลำดับเลือกแต่ละค่าแยกกัน:

1. สาขาและหมวดตรงกัน
2. หมวดของหน่วยงาน
3. สาขา
4. แบบหลักของหน่วยงาน

ในระดับเดียวกันเลือกวันที่เริ่มใช้ล่าสุดที่ไม่เกินวันที่ใช้งาน แบบเลขใช้วันที่ออกเลข ส่วนค่าเสื่อมใช้วันเริ่มคิดค่าเสื่อม (หากยังไม่ระบุใช้วันที่ออกเลข) ช่องที่ไม่ได้กำหนดรับค่าจากระดับรองลงมา

ตัวอย่าง: บัญชีหลักใช้เลข 10 หลัก หมวดอาคารใช้ 8 หลัก และสาขา ก. ในหมวดเครื่องมือแพทย์ใช้ 15 หลักได้ แต่ละกรณีเลือกกฎค่าเสื่อมต่างกันได้ แก้หลักเกณฑ์ที่หน้า **อายุใช้งานและค่าเสื่อม** แล้วกลับมาผูกการใช้กับหน่วยงาน/สาขา/หมวด ไม่มีการสร้างอัตราจากเลขครุภัณฑ์หรือจาก PDF คู่มือออกเลข

การแก้เงื่อนไขมีเลขฉบับและตรวจการบันทึกพร้อมกัน หากมีการแก้จากอีกหน้าต่างจะไม่เขียนทับร่าง ให้โหลดค่าล่าสุดก่อนแก้ใหม่ ยกเลิกเงื่อนไขได้โดยแก้แล้วเอาเครื่องหมายเปิดใช้ออก; ข้อมูลประวัติไม่ถูกลบ

## 4. บัญชีชนิดและคุณลักษณะ

แท็บ **บัญชีชนิด / คุณลักษณะ** แยกรายการตามบัญชีหน่วยงานและหมวด โรงพยาบาลมีรายการตั้งต้นจาก RAR ส่วน PDF ของศูนย์แพทย์แสดงบัญชีอ้างอิงตามตัวเลขพิมพ์จริง คงชนิด 4 หลัก เช่น `0204` ไว้ ไม่แปลงเป็นชนิด 3 หลักอัตโนมัติ

ค้นบัญชีอ้างอิง PDF ได้พร้อมหน้าเอกสาร ตารางที่อ่านได้เก็บเป็นรายการอ้างอิง ส่วนไฟล์ PDF ต้นฉบับเก็บแยกในชุดสำรอง รายการที่ข้อความอ่านได้ยังไม่ครบไม่ถือว่าไม่มีในต้นฉบับ การจับคู่ไปออกเลขต้องใช้กฎที่หน่วยงานรับรอง

เพิ่ม/แก้ชื่อชนิด รหัสอ้างอิง ค่าตัวแปร ข้อความเงื่อนไขและที่มาได้ การแก้เก็บค่าก่อน/หลังใน `account_events` ไม่แก้แถวต้นทางของทะเบียนหรือข้อความในไฟล์ต้นฉบับ และไม่เปลี่ยน snapshot ของชิ้นที่บันทึกแล้ว

หน้า **บัญชีเลขเดิม** ยังคงไว้สำหรับทะเบียนที่ยังไม่แยกบัญชีหน่วยงาน บัญชีนั้นไม่ใช่ตัวกำหนดแบบเลขของบัญชีใหม่

## 5. เพิ่มครุภัณฑ์และดูค่าเสื่อมประจำชิ้น

เลือกเจ้าของบัญชีเลข (หรือเลือกเลขเดิม/ยังไม่แยกหน่วยงานอย่างชัดเจน) หมวด สาขา และชนิด/คุณลักษณะ ระบบแสดงแบบเลข เหตุผลที่เลือก และหลักเกณฑ์ค่าเสื่อม หากไม่มีรายการในบัญชีกรอกค่าตัวแปรเองได้ หรือเก็บเลขเดิมตามทะเบียนโดยไม่บังคับแปลงรูปแบบ

ระบุราคาทุนและวันเริ่มคิดค่าเสื่อมเมื่อมีข้อมูล ผู้มีบทบาทเจ้าหน้าที่พัสดุเลือกหลักเกณฑ์ยกเว้นรายชิ้นได้พร้อมเหตุผลบังคับ ระบบบันทึกค่าหลักเกณฑ์และแบบเลขเป็น snapshot พร้อมรายการ ไม่เขียนทับยอดนำเข้าเดิม

รายละเอียด / QR แสดงบัญชี รุ่นแบบเลข หลักเกณฑ์ และตัวอย่างค่าเสื่อมจาก snapshot วิธีตัวอย่างใช้วันจริงหาร 365 ไม่นับวันเริ่มต้น จำกัดไม่ต่ำกว่ามูลค่าคงเหลือ แสดงวันที่และวิธีคิด ไม่ใช่การลงบัญชีหรือการรับรองเกณฑ์ราชการ วิธีรายกรณีและรายการไม่มีหลักเกณฑ์ไม่คำนวณอัตโนมัติ

ฟอร์มรายละเอียด / QR คงเลขและหมวดไว้ ส่วนการแก้เลข หมวด บัญชี และหลักเกณฑ์ให้ใช้ **แก้ไขข้อมูล** ในทะเบียน พร้อมระบุเหตุผลและตรวจรายการซ้ำ โดยไม่เขียนทับข้อมูลต้นทาง ดู [คู่มือหน้าตาราง](simple-workspace-guide.md)

## 6. สำรองและกู้คืน

แท็บ **สำรอง / ไฟล์ต้นทาง** ฝากไฟล์ต้นฉบับพร้อมเลือกหน่วยงานและหน้าที่เอกสาร: ทะเบียนจริง บัญชีอ้างอิง หรือหลักเกณฑ์ค่าเสื่อม ไฟล์เก็บเป็นไบต์เดิมและ SHA-256 นอก web root การฝากไฟล์ไม่ใช่การนำเข้าทะเบียนหรือการแปลงเลข

**ดาวน์โหลดชุดสำรอง** เก็บ SQLite ที่สอดคล้องกันทุกตารางและไฟล์ที่ฝากไว้ พร้อม manifest ระบุ hash/ขนาด/จำนวนรายการ รวมประวัติงานซ่อม QR และข้อมูลต้นทาง แสดงจำนวนรายการของฐานปัจจุบันก่อนดาวน์โหลด หากเปิดฐานสาธิตจะไม่มีทะเบียนจริงเพิ่มเอง

ชุดที่ผู้ดูแลเตรียมแยกไว้อยู่ใน `<ASSET_DB_PATH>.backups/*.zip` ปรากฏแยกพร้อมจำนวนรายการของชุดนั้น ดาวน์โหลดได้โดยไม่เปลี่ยนฐานปัจจุบัน ไฟล์เหล่านี้และข้อมูลจริงไม่ขึ้น GitHub อัตโนมัติ

กู้คืนไปที่ไฟล์ใหม่ใน PowerShell:

```powershell
py -3 scripts/restore-backup.py "C:\Users\ชื่อผู้ใช้\Downloads\Smart-Asset-backup.zip" --output "D:\Smart-Asset-Data\restored.sqlite3"
```

สคริปต์ตรวจ hash ขนาด จำนวนรายการ และความสัมพันธ์ใน SQLite ก่อนคืนข้อมูล ห้ามปลายทางมีอยู่แล้ว ไม่เขียนทับฐานที่กำลังทำงาน จากนั้นหยุดเซิร์ฟเวอร์และเลือกฐานที่คืนไว้:

```powershell
$env:ASSET_DB_PATH = "D:\Smart-Asset-Data\restored.sqlite3"
.\.venv\Scripts\python.exe server.py
```

ต้องเก็บโฟลเดอร์ `restored.sqlite3.sources` คู่กับฐาน เพราะเก็บต้นฉบับสำหรับสำรองรอบถัดไป LINE access token/channel secret ที่อยู่ใน environment ไม่รวมในชุดฐานข้อมูล ต้องตั้งในเครื่องปลายทางเอง

## 7. การอัปเกรดฐานเดิม

หยุดเซิร์ฟเวอร์ `git pull` แล้วรันใหม่ตามคำสั่งเดิม ระบบสำรอง SQLite ไปที่ `<ASSET_DB_PATH>.backups/before-account-numbering-*.sqlite3` ก่อนเปลี่ยนข้อจำกัดเลข ย้ายโครงสร้างแบบ transaction รักษา ID, QR, source rows และยอดค่าเสื่อมเดิม

ทะเบียนจากชื่อ Workbook ในชุด RAR ที่ยืนยันแล้วผูกบัญชีโรงพยาบาลสุรินทร์ เลขเดิมที่ซ้ำคงไว้รอตรวจ ไม่เปลี่ยนเลขและไม่ทิ้งแถว แหล่งอื่นที่ยังไม่ทราบบัญชีคงสถานะยังไม่แยกหน่วยงาน ระบบไม่เลือกสาขาจากข้อความที่ตั้งโดยเดาเอง
