# การแจ้งเตือนในแอปและ LINE

กระดิ่งในแอปใช้ได้โดยไม่ต้องเชื่อมต่อ LINE ส่วน LINE ใช้ **LINE Official Account + Messaging API** และปิดไว้เริ่มต้น ไม่ใช้ LINE Notify ซึ่งยุติบริการแล้วเมื่อ 31 มีนาคม 2568 การติดตั้งโค้ดเพียงอย่างเดียวยังไม่เชื่อมบัญชีหรือส่งข้อความจริง

## 1. เตรียมบัญชีและเซิร์ฟเวอร์

เปิดใช้งาน Messaging API ของ LINE OA แล้วเตรียม Channel access token และ Channel secret ของช่องทางเดียวกัน กำหนดบนเครื่องที่รัน `server.py` ด้วยตัวแปร `LINE_CHANNEL_ACCESS_TOKEN` และ `LINE_CHANNEL_SECRET` ตามลำดับ ห้ามใส่คีย์ใน Git, ภาพหน้าจอ หรือแชต หน้าแอปแสดงเพียงว่ากำหนดแล้วหรือยัง ไม่มีช่องเก็บคีย์ลงฐานข้อมูล

ตัวอย่าง PowerShell รับค่าโดยไม่แสดงบนจอ:

```powershell
$lineAccess = Read-Host "LINE Channel access token" -AsSecureString
$env:LINE_CHANNEL_ACCESS_TOKEN = [System.Net.NetworkCredential]::new("", $lineAccess).Password
$lineSecret = Read-Host "LINE Channel secret" -AsSecureString
$env:LINE_CHANNEL_SECRET = [System.Net.NetworkCredential]::new("", $lineSecret).Password
```

จากนั้นรันคำสั่งเปิดแอปชุดเดิมใน PowerShell หน้าต่างเดียวกัน โดยใช้ `ASSET_DB_PATH` ของฐานข้อมูลเดิมที่ต้องการ ตัวแปรเหล่านี้อยู่เฉพาะกระบวนการ/หน้าต่างนี้ หากรันเป็นบริการให้กำหนดคีย์ผ่านระบบจัดการความลับของบริการและเริ่มบริการใหม่ แอปไม่ได้อ่านไฟล์ `.env` อัตโนมัติ

เซิร์ฟเวอร์ต้องออก HTTPS ไป `api.line.me` ได้ และต้องทำงานอยู่จึงประมวลผลคิวได้ ลิงก์แอปต้องเป็น HTTPS ที่โทรศัพท์ผู้รับเข้าถึงได้ เช่น `https://assets.example.go.th` โดยไม่ต่อ path/query การรันที่ `127.0.0.1:8000` อย่างเดียวไม่ทำให้ LINE หรือโทรศัพท์เข้าถึงได้

**ต้นแบบนี้ยังไม่มีล็อกอินจริง** ตัวเลือกบทบาทคือการจำลอง ไม่ใช่สิทธิ์รายบุคคล ก่อนใช้ข้อมูลจริงต้องจัดการยืนยันตัวบุคคลและจำกัดการเข้าถึงแอป เช่น ผ่านระบบยืนยันตัวตนของหน่วยงานหรือเครือข่ายภายใน ห้ามเปิดทั้งต้นแบบสู่สาธารณะเพียงเพื่อรับ webhook สามารถแยกเส้นทาง webhook ที่ตรวจลายเซ็นให้ LINE เข้าถึงได้ ขณะที่แอปอยู่หลังระบบยืนยันตัวตน

## 2. ตั้งค่าผู้รับ

1. เลือกบทบาท **เจ้าหน้าที่พัสดุ** แล้วเปิด **ตั้งค่า → เชื่อมต่อ LINE OA**
2. บันทึกที่อยู่ HTTPS ของแอป โดยยังปิดส่งอัตโนมัติไว้
3. เพิ่มผู้รับ เลือกบทบาทที่ต้องการติดตาม ระบุชื่อเรียกและ LINE user ID (`U…`), group ID (`C…`) หรือ room ID (`R…`) ต้องเป็น ID ของ Messaging API ซึ่งต่างจากชื่อแสดงผล, `@บัญชี` และ QR เพิ่มเพื่อน
4. ผู้รับรายบุคคลต้องเพิ่มเพื่อน OA หรือเข้าเงื่อนไขที่ LINE อนุญาต สำหรับกลุ่มให้เปิดอนุญาต OA เข้าร่วมกลุ่มใน LINE Developers และเชิญ OA เข้ากลุ่มก่อน เลือกกลุ่มให้ตรงกับข้อมูลที่สมาชิกควรได้รับ
5. บันทึก เลือกผู้รับที่บันทึกแล้ว และกด **ส่งข้อความทดสอบ** ตรวจบนโทรศัพท์จริงก่อนเปิดส่งอัตโนมัติ ปุ่มนี้ส่งเฉพาะข้อความทดสอบและไม่เปลี่ยนสถานะงาน

กำหนดได้ไม่เกิน 20 คู่บทบาท/ปลายทาง ผู้รับกลุ่มเดียวกันที่ติดตามหลายบทบาทจะไม่รับข้อความซ้ำสำหรับคีย์เหตุการณ์เดียวกัน การจับคู่ตามบทบาทไม่ได้ระบุผู้รับผิดชอบรายบุคคลโดยอัตโนมัติ

### ค้นหา ID จาก webhook

หากไม่มี ID สามารถตั้ง Webhook URL ใน LINE Developers เป็น `https://ชื่อโฮสต์ที่รับ-webhook/api/line/webhook` แล้วเปิด Use webhook และตรวจ Verify โดยต้องกำหนด Channel secret ไว้ก่อน เมื่อ OA ได้รับเหตุการณ์จากผู้ใช้/กลุ่ม ให้กดโหลดค่าล่าสุดในหน้าตั้งค่าแล้วเลือก ID ที่ตรวจพบ

หน้าตั้งค่าแสดง URL ที่คำนวณจากที่อยู่แอป หากใช้โฮสต์ webhook แยกต่างหากให้ตั้ง URL จริงที่ LINE Developers เอง ระบบตรวจ `X-Line-Signature` ด้วย HMAC-SHA256 จากเนื้อหาเดิมก่อนรับข้อมูล เก็บเฉพาะ ID ปลายทาง ประเภท และเวลาพบล่าสุด ไม่เก็บข้อความแชต ไม่ตอบกลับ และไม่รับคำสั่งอนุมัติผ่าน webhook เหตุการณ์กลุ่มเก็บ group ID โดยไม่เก็บ user ID ของผู้ส่งในกลุ่ม

## 3. การแจ้งและอนุมัติ

กระดิ่งแสดงงานตามบทบาท เช่น รับแจ้งซ่อม รอมอบหมาย รออนุมัติค่าใช้จ่าย/ครุภัณฑ์ใหม่ รับรองงานซ่อม และ PM/ตรวจนับใกล้ถึงกำหนดหรือเกินกำหนด LINE ใช้เหตุการณ์จากแหล่งเดียวกันและส่งเมื่อพบเหตุการณ์ใหม่หลังเปิดใช้งาน

เมื่อเปิด LINE หรือแก้ไขการตั้งค่า ระบบถือรายการปัจจุบันเป็นจุดเริ่มต้น ไม่ส่งงานค้างทั้งหมดย้อนหลัง งานค้างยังดูได้ในกระดิ่ง การเปลี่ยนค่าจะข้ามคิวเดิมที่ยังไม่เริ่มส่งและเริ่มติดตามตามค่าใหม่ การกดบันทึกค่าเดิมไม่ล้างคิว ข้อความที่เริ่มส่งออกไปแล้วอาจหยุดไม่ทัน

ข้อความประกอบด้วยชื่อแอป ประเภทแจ้งเตือน เลขอ้างอิง กำหนดวันถ้ามี และลิงก์เปิดรายการ ไม่มีข้อมูลติดต่อหรือรายละเอียดภายในใบซ่อม เมื่อกดลิงก์ ผู้ใช้กลับเข้าแอปเพื่อดำเนินงาน/อนุมัติและต้องอยู่ในบทบาทที่เกี่ยวข้อง ลิงก์ไม่เปลี่ยนบทบาทและไม่อนุมัติเอง

สถานะอ่านในแอปแยกจากสถานะส่ง LINE และใช้ร่วมกันภายในบทบาทจำลองเดียวกัน การอ่าน/รับข้อความไม่เท่ากับอนุมัติ ไม่มีการตรวจว่าผู้รับอ่านข้อความ LINE แล้ว

## 4. คิวส่งและแก้ปัญหา

ดูรายการส่งล่าสุดในหน้าตั้งค่า คำว่า **LINE รับคำขอแล้ว** หมายถึง API รับคำขอ ไม่รับประกันว่าปรากฏบนโทรศัพท์หรืออ่านแล้ว การส่งใช้โควตาของบัญชี OA ตามแพ็กเกจ

- `รอส่ง` / `รอลองใหม่`: เซิร์ฟเวอร์ตรวจคิวเป็นระยะ หากเครือข่ายขัดข้อง, HTTP 429 หรือ 5xx จะลองใหม่พร้อมเพิ่มระยะรอ รวมสูงสุด 5 ครั้งอัตโนมัติ
- `ข้าม`: งานเปลี่ยนขั้นแล้ว หรือเปลี่ยนการตั้งค่า/ผู้รับ ระบบไม่ส่งข้อความเก่าที่ชวนให้ดำเนินงานผิดขั้น
- `ล้มเหลว`: ตรวจคีย์/บัญชีและข้อผิดพลาดก่อนกดส่งซ้ำ HTTP 401/403 ให้ตรวจ token และสิทธิ์ของบัญชี HTTP 429 ให้ตรวจโควตาและอัตราการเรียก
- ปุ่มส่งซ้ำใช้ได้เฉพาะรายการที่งานและผู้รับยังตรงกับค่าปัจจุบัน ใช้ข้อความและ retry key เดิมเพื่อลดการส่งซ้ำ ไม่สร้างเหตุการณ์อนุมัติใหม่

คิวอยู่ใน SQLite จึงคงอยู่เมื่อเริ่มเซิร์ฟเวอร์ใหม่ มีการจองคิวเพื่อกัน worker ส่งพร้อมกัน และใช้ `X-Line-Retry-Key` เดิมเมื่อกู้คิวหรือส่งซ้ำ หากเกิน 23 ชั่วโมงจากเริ่มลองส่งจะหยุดเพื่อหลีกเลี่ยงการส่งซ้ำหลังช่วงเก็บ retry key ของ LINE ต้องตรวจข้อความผู้รับก่อนดำเนินการต่อ ไม่ลบประวัติแล้วส่งใหม่โดยไม่ตรวจสอบ

ถ้าไม่พบ ID ในรายการ ให้ตรวจ secret, URL ที่ LINE เข้าถึงได้, Use webhook และเหตุการณ์หลังตั้งค่า ถ้าไม่ส่งอัตโนมัติ ให้ตรวจสถานะเปิดใช้งาน, token, ผู้รับ, การทำงานของเซิร์ฟเวอร์ และทดลองสร้างเหตุการณ์ใหม่หลังเปิด LINE ไม่ใช่รอให้ส่งงานค้างเดิม

คู่มือ API: [Messaging API reference](https://developers.line.biz/en/reference/messaging-api/), [Verify webhook signature](https://developers.line.biz/en/docs/messaging-api/verify-webhook-signature/), [Retry failed API requests](https://developers.line.biz/en/docs/messaging-api/retrying-api-request/)
