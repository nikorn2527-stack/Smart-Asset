# หมวดครุภัณฑ์ รหัส FSN และเลขประจำครุภัณฑ์

อ้างอิงคู่มือการกำหนดรหัสครุภัณฑ์ที่ผู้ใช้แนบ หน้า PDF 2–3 และไฟล์ Excel ใน `ครุภัณฑ์แยกประเภท.rar` การเพิ่มหมวดไม่สร้างรหัส FSN และไม่เลือกหลักเกณฑ์ค่าเสื่อมให้เอง

| ข้อมูล | หน้าที่ | ที่มา / การเพิ่ม |
|---|---|---|
| หมวดครุภัณฑ์ | จัดกลุ่ม เช่น ครุภัณฑ์สำนักงาน | ชื่อหมวดจาก workbook หรือเพิ่มที่ ตั้งค่า → หมวดและเอกสารอ้างอิง → เพิ่มหมวด |
| FSN ชุดที่ 1: `7110` | กลุ่ม/ประเภท: `71` กลุ่มเครื่องตกแต่ง และ `10` ประเภทเครื่องตกแต่งสำนักงาน | ค้นจากคู่มือ/บัญชีที่หน่วยงานใช้ ไม่สร้างเลขขึ้นจากลำดับหมวดในแอป |
| FSN ชุดที่ 2: `002` | ชนิด เช่น ตู้เก็บเอกสารที่เป็นลิ้นชัก | ค้นจากบัญชีชนิดที่มีอยู่ หรือบันทึกพร้อมหลักฐานของหน่วยงาน |
| FSN ชุดที่ 3: `0001` | รายละเอียดชนิด เช่น ตู้ 4 ลิ้นชัก ตามตัวอย่างในคู่มือ | ใช้เลขเดิมเมื่อคุณลักษณะเดียวกัน; คุณลักษณะใหม่จึงกำหนดเลขรายละเอียดใหม่โดยไม่ซ้ำในชุดกลุ่ม/ชนิดนั้น |
| เลขประจำครุภัณฑ์ | ระบุทรัพย์สินแต่ละชิ้น | ทะเบียนส่วนใหญ่ใช้ `4-3-4-4` แอปรองรับ FSN + ลำดับประจำชิ้น หรือระบุเลขเดิมด้วยตนเอง |
| QR | ลิงก์ประจำชิ้นสำหรับดูข้อมูล/แจ้งซ่อม | สร้างจาก token แยกต่างหาก การเปลี่ยนชื่อหรือเลขทะเบียนจึงไม่ต้องเปลี่ยน QR |

ตัวอย่างสมมติ: ตู้ 4 ลิ้นชัก 2 ตัวใช้ FSN `7110-002-0001` เหมือนกัน แต่เลขประจำครุภัณฑ์เป็น `7110-002-0001-0001` และ `7110-002-0001-0002` พร้อม QR คนละลิงก์ ตัวอย่างนี้อธิบายพฤติกรรมแอป ไม่ใช่การอ้างว่าคู่มือบังคับเลขส่วนที่ 4 สำหรับทุกหน่วยงาน

## ความสัมพันธ์ที่ระบบรองรับ

หมวดเป็นการจัดกลุ่มของหน่วยงาน ไม่ใช่เลขชุดที่ 1 และไม่จำเป็นต้องสัมพันธ์แบบหนึ่งต่อหนึ่ง หมวดเดียวใช้ได้หลายกลุ่ม/ประเภท เช่น บัญชีครุภัณฑ์การศึกษามีทั้งอุปกรณ์สำนักงานและอุปกรณ์แพทย์ รหัสจำแนกเดียวกันอาจใช้ในหลายหมวดได้เมื่อมีหลักฐานรองรับ จึงห้ามสร้างเลขชุดที่ 1 จากลำดับหมวดหรือเดาด้วยชื่อหมวด

แอปมีบัญชีตั้งต้นจากไฟล์แยกประเภทที่ให้มา 19 หมวดอยู่แล้ว เลือกหมวดและชนิดตามต้นทางได้ทันที ไม่ต้องนำเข้าทะเบียนรายชิ้นก่อน รายละเอียด [บัญชีตั้งต้น](../reference-data/README.md)

ระบบใช้ข้อมูลจากแหล่งต่อไปนี้:

1. **บัญชีตั้งต้นจากข้อมูลเดิม**: หมวด ชนิด และรหัสที่ใช้จริงใน Excel เชื่อมตามต้นทาง เก็บชื่อชนิดทุกชื่อเมื่อรหัสเดียวมีหลายชื่อ ชนิดที่ยังไม่มีเลขครบแสดงให้ตรวจ ไม่กำหนดเลขแทน
2. **บัญชีอ้างอิง PDF**: คงเลข ชื่อ หน้า และข้อความต้นฉบับ ตัวอย่างรหัสเต็มในคู่มือไม่ได้ยืนยันความหมายเลขชุดที่ 3 ของหน่วยงาน และบางแถวมีชนิด 4 หลัก จึงไม่ตัดหลักเอง
3. **รหัสที่พบในทะเบียน**: อ่าน 3 ชุดแรกจากเลขประจำชิ้นที่ครบรูปแบบ หรือใช้ `fsn_code` ที่บันทึกไว้ แยกตามหมวดจากรายการนำเข้าหรือรายการที่ผ่านขั้นรออนุมัติแล้ว แสดงตัวอย่าง ชื่อ รายละเอียด ไฟล์และแถวต้นทาง โดยไม่เขียนทับเลขเดิม ชื่อที่แสดงเป็นตัวอย่างการใช้รหัส ไม่ใช่การรับรองว่ารายการทั้งหมดมีคุณลักษณะเหมือนกัน
4. **บัญชีหน่วยงานที่กำหนดไว้**: รหัสเต็ม ชื่อ/คุณลักษณะ และหลักฐาน เชื่อมหมวดผ่าน `category_fsn_codes` รองรับหลายหมวดต่อรหัสและหลายรหัสต่อหมวด เลขที่เคยเพิ่มโดยไม่ได้ผูกหมวดต้องกำหนดหมวดก่อนนำไปใช้

## หน้าที่ของแต่ละหน้า

- **ตั้งค่า → จัดการเลขครุภัณฑ์**: เจ้าหน้าที่ดูบัญชีเลขชุดที่ 1–3 เพิ่มชนิด/คุณลักษณะพร้อมหลักฐาน กด **ดูเลข / จัดการ** เพื่อตรวจเลขถัดไปและที่มา หรือ **เพิ่มคุณลักษณะในชนิดนี้** เพื่อคงเลขชุดที่ 1–2 แล้วกำหนดชุดที่ 3 ใหม่ ไม่มีช่องให้ตั้งลำดับชิ้นชุดที่ 4 ด้วยตนเองในบัญชีนี้
- **เพิ่มครุภัณฑ์**: เลือกหมวดและชื่อรายการจากบัญชี ระบบเติมเลขให้แต่ละชิ้น หากไม่พบรายการให้กดเพิ่มในบัญชีก่อน
- **ตั้งค่า → หมวดและเอกสารอ้างอิง**: จัดกลุ่มหมวดและเปิดอ่านบัญชีเลขตามเอกสารต้นฉบับ

## เพิ่มอุปกรณ์ใหม่

1. เปิด **เพิ่มครุภัณฑ์** เลือกหมวด ระบบมีชนิดและรหัสตั้งต้นของหมวดให้แล้ว และอ่านบัญชีรหัสของหมวดนั้นทั้งหมด ไม่อาศัยเฉพาะทรัพย์สิน 150 รายการล่าสุดหรือหน้าแรกของบัญชี
2. เลือก **ชนิดครุภัณฑ์ตามบัญชีเดิม** เพื่อกรองรายการ แล้ว **เลือกชื่อชนิด/คุณลักษณะ** เช่น ตู้เหล็ก 4 ลิ้นชัก ระบบเติมเลขชุดที่ 1–3 ให้ และแสดงเลขทั้ง 4 ชุดพร้อมคำอธิบาย ไม่ต้องเลือกช่องตัวเลขทีละชุด ชื่อครุภัณฑ์เติมให้และแก้ไขเพิ่มเติมได้
3. ตรวจชื่อ/คุณลักษณะ ตัวอย่างรายการเดิม และที่มา หากตรงกันให้ใช้รหัสเดิม จะเห็นตัวอย่างเลขชุดที่ 4 ถัดไป เลขนี้ยังไม่ใช่การจอง และเริ่มต่อจากลำดับสูงสุดในบัญชีเดิมที่มีมาให้ ระบบตรวจจากทะเบียนทุกหมวดอีกครั้งภายใต้ transaction เมื่อบันทึก รวมรายการรออนุมัติและเลขที่มี suffix `/` หรือ `.`
4. ถ้าไม่พบรหัส ให้ไป **ตั้งค่า → จัดการเลขครุภัณฑ์** ดูตาราง **บัญชีชนิดและคุณลักษณะ** ก่อน หากเป็นคุณลักษณะใหม่ให้ **เพิ่มชนิด / คุณลักษณะ** ระบุหมวด 4–3–4 หลัก ชื่อ/คุณลักษณะ และหลักฐาน ไม่ให้เลขชุดที่ 3 เปลี่ยนทุกครั้งที่ซื้อเพิ่มชนิดเดิม
5. รายการอ้างอิง PDF ใช้ปุ่ม **กำหนดใช้รหัสนี้กับหมวด** เพื่อคัดลอกมาตรวจชื่อ/หลักฐานก่อนกำหนดใช้ ส่วนรหัสที่เป็นบัญชีหน่วยงานอยู่แล้วใช้ปุ่มเดียวกันเพื่อผูกหมวดเพิ่มเติมโดยคงชื่อและเลขเดิม เจ้าหน้าที่ต้องตรวจความหมายกับหลักฐาน ระบบไม่รับรองความหมายจากเลขอย่างเดียว
6. ถ้าเลขเดิมมีรูปแบบอื่น เช่น ชนิด 4 หลัก รหัสอาคาร หรือรหัสเฉพาะ ให้เลือก **มีแล้ว — ใช้เลขเดิม** คงเลขเต็มตามต้นฉบับ โหมดนี้ใช้เลขเดิมโดยไม่บังคับเลือกรหัสจำแนก ไม่ต้องแต่งเลข 3 ชุดให้ครบ

หมวดที่ยังไม่มีข้อมูลจะแสดงว่ายังไม่มีรหัสผูกไว้ ไม่เติมตัวอย่าง PDF เป็นรหัสใช้งานโดยอัตโนมัติ หน้าจอแสดงจำนวนรายการที่อ่านรูปแบบได้และจำนวนที่ใช้รูปแบบอื่น เพื่อไม่ทำให้เข้าใจว่าทะเบียนรูปแบบอื่นหายไป ค่าทั้งหมดอิงฐานที่กำลังเปิดอยู่ การปรับหน้าจอนี้ไม่ได้ติดตั้งข้อมูลส่วนตัวของหน่วยงานลงในฐานสาธิต

## การรักษาข้อมูลเดิม

การอัปเดตแอปเพิ่มช่อง `assets.fsn_code` แยกจาก `assets.code` โดยไม่แก้เลขทะเบียนย้อนหลัง และไม่ถือว่าเลข 3 ชุดของข้อมูลสาธิตเดิมเป็นเลขประจำชิ้นแบบใหม่ บัญชีใน PDF บางแถวมีชนิด 4 หลัก ระบบแสดงตามต้นฉบับและไม่ตัดหลักให้เป็น 3 หลักเอง

ฐานนำเข้ารอบนี้เก็บ 66,395 แถวต้นทาง: ครุภัณฑ์ 66,394 รายการ และหัวตาราง Software 1 แถวที่เก็บแยกเป็น `record_kind=header` มีรหัสซ้ำ 5 แถวและรหัสว่าง 1 แถวที่ยังคงไว้ ไม่มีการรวมแถวหรือแต่งเลขให้ ข้อมูล Software ที่มีหัวตารางใช้ชื่อหัวคอลัมน์จริงแทนการเดาตำแหน่ง

ฐานจากเอกสาร 2 ชุดนี้ไม่มีบัญชีหลักเกณฑ์ค่าเสื่อมหรือ JSON ที่ตรวจทานแบบทะเบียนคุม PDF จึงไม่สร้างกฎค่าเสื่อมหรืออ้างว่าเชื่อมเอกสารสแกนแล้ว ค่า acquisition/ค่าเสื่อมเดิมที่มีใน Excel ยังคงเก็บไว้ เปิดฐานนำเข้าแล้วระบบจะไม่เติมใบแจ้งซ่อมหรือใบสำรวจสาธิต

## คำอธิบายและเงื่อนไขที่แก้ไขได้

หน้าจัดการแสดงข้อความหลักเกณฑ์จากคู่มือจริง และมีคำอธิบาย/เงื่อนไขของหมวดและแต่ละรหัสให้เจ้าหน้าที่แก้ไข พร้อมระบุเอกสาร ข้อ/หน้า และเหตุผล เก็บข้อความต้นฉบับและประวัติแยกจากฉบับใช้งาน ไม่เปลี่ยนเลขหรือการจัดหมวดของทะเบียนเดิม รายละเอียดใน [คู่มือใช้งาน](../MANUAL.md#แก้ไขข้อความและเงื่อนไขที่ใช้ประกอบการออกเลข)
