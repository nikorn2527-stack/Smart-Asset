# หลักเกณฑ์ร่วม ทะเบียนแยกเจ้าของ และการนำเข้า

## โครงสร้างที่ใช้งาน

**PDF เป็นคู่มือข้อกำหนดการจำแนกและออกเลข ส่วน ZIP/RAR เป็นทะเบียนอุปกรณ์จริง** การเป็นคนละไฟล์ไม่ได้แปลว่าต้องเป็นคนละระเบียบหรือคนละเจ้าของบัญชี ระบบจึงใช้หลักเกณฑ์และบัญชีอุปกรณ์กลางร่วมกัน ส่วนทรัพย์สิน เอกสาร งานซ่อม PM และสิทธิ์เข้าถึง แยกตามองค์กรและสาขา

- เลขชุดที่ 1–3 คือเลขจำแนกกลุ่ม/ประเภท ชนิด และคุณลักษณะตามคำอธิบายในคู่มือ
- เลขชุดที่ 4 ในทะเบียนจริงคือเลขรันของแต่ละชิ้น เลขรันพิจารณาทะเบียนที่มีอยู่ขององค์กรเจ้าของ ไม่ใช้ทรัพย์สินขององค์กรอื่นมานับ
- ต้นฉบับ PDF มี 907 แถวในบัญชีท้ายเล่ม รวม 903 คู่รหัสที่ไม่ซ้ำ เก็บชื่อ รหัส หน้าต้นฉบับ และข้อความตามพิมพ์ครบ รวมรหัสชนิด 4 หลัก เช่น `0204` ในตาราง ไม่ตัดศูนย์หรือแปลงเป็น 3 หลักเอง
- บัญชีชนิดที่มีรหัสใช้งานจากทะเบียนเดิมใช้ร่วมกันได้ทุกองค์กร โดยยังไม่เพิ่มทะเบียนทรัพย์สินจริงจากรายการบัญชีชนิดเหล่านี้ การเพิ่มหรือแก้บัญชีกลางใช้ผู้ดูแลระบบส่วนกลาง ข้อมูลและเลขของทรัพย์สินที่สร้างแล้วไม่เปลี่ยนตามการแก้ชื่อในบัญชีกลาง
- หน่วยงานกำหนดรายละเอียด/คุณลักษณะบางส่วนได้ตามที่คู่มืออธิบาย การแก้แบบขั้นสูงหรือข้อยกเว้นไม่เปลี่ยนเลขในทะเบียนเดิม และไม่สร้างระเบียบคนละชุดเพราะเป็น PDF กับ ZIP

## เริ่มใช้งาน Local

หยุดเซิร์ฟเวอร์เดิมด้วย `Ctrl+C` แล้วรันในโฟลเดอร์โครงการ:

```powershell
git pull
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe server.py
```

ใช้ `ASSET_DB_PATH` เดิมที่เคยตั้งไว้ เพื่อเปิดฐานข้อมูลเดิม ระบบเพิ่มตารางใหม่โดยรักษา ID เลขครุภัณฑ์ QR และข้อมูลต้นทางเดิม ไม่ต้องนำเข้าข้อมูลเดิมซ้ำ

การเข้าสู่ระบบเปิดเป็นค่าเริ่มต้น เปิดหน้าแอปจากเครื่องที่รันระบบแล้วสร้างชื่อผู้ดูแลและรหัสผ่านครั้งแรกด้วยตนเอง รหัสผ่านอย่างน้อย 10 ตัวอักษร ไม่มีบัญชีหรือรหัสผ่านสำเร็จรูป การตั้งผู้ดูแลครั้งแรกผ่านเว็บรับเฉพาะคำขอจากเครื่องที่รันเซิร์ฟเวอร์ ถ้าติดตั้งบนเครื่องปลายทางที่เข้าคอนโซลได้ ให้ใช้คำสั่งสร้างผู้ดูแลด้านล่าง

ตัวแปร `ASSET_AUTH_REQUIRED=0` มีไว้เฉพาะการทดสอบเดิมแบบแยกสภาพแวดล้อม ซึ่งข้ามการเข้าสู่ระบบและสิทธิ์ทั้งหมด อย่าใช้ค่านี้กับข้อมูลจริง ชุดทดสอบสิทธิ์จริงเปิด `ASSET_AUTH_REQUIRED=1` แยกจากชุดทดสอบฟังก์ชันเดิมอย่างชัดเจน

## องค์กรและสาขา

ผู้ดูแลเพิ่มองค์กร/สาขาที่ **ตั้งค่า → ตั้งหมวด เลขครุภัณฑ์ และค่าเสื่อม → หน่วยงาน / สาขา** องค์กรใหม่จากหน้านี้ได้รับบัญชีชนิดกลางและแบบเริ่มต้น `4–3–4–4` โดยไม่ต้องคัดระเบียบขึ้นใหม่

ชื่อองค์กรที่ตั้งไว้ก่อนหน้ายังคงอยู่ ไม่มีการย้ายเจ้าของทรัพย์สินเดิมเพราะปรับความเข้าใจเรื่อง PDF เลือกชื่อเจ้าของทะเบียนจริงตอนนำเข้า ผู้ดูแลใช้ปุ่มองค์กรด้านบนเพื่อเลือกองค์กร/สาขาที่กำลังทำงานหรือดูภาพรวมทั้งระบบตามสิทธิ์ การสลับขอบเขตโหลดหน้าใหม่เพื่อล้างร่างและข้อมูลจากขอบเขตก่อนหน้า

## ผู้ใช้งานและสิทธิ์

เข้า **ตั้งค่า → ผู้ใช้งานและสิทธิ์** ผู้ดูแลระบบเพิ่มผู้ใช้และกำหนดองค์กร/สาขาได้หลายขอบเขตต่อคน แต่ละขอบเขตเลือกสิทธิ์ดู เพิ่ม แก้ไข อนุมัติ ส่งออก จัดการตั้งค่า/ผู้ใช้ และดำเนินงานซ่อม/PM แยกกัน

- สิทธิ์ **ดูได้ทุกองค์กร** ให้การมองเห็นส่วนกลาง โดยไม่ได้ให้สิทธิ์แก้ไขหรือส่งออกทั้งระบบเพิ่มเอง หากต้องแก้ข้อมูลเฉพาะองค์กร ให้เพิ่มสิทธิ์องค์กรนั้นแยกไว้
- **ผู้ดูแลระบบส่วนกลาง** ดูแลผู้ใช้ องค์กร บัญชีชนิดกลาง หลักเกณฑ์กลาง การเชื่อมต่อ LINE และสำรองฐานทั้งระบบ
- **ผู้ดูแลองค์กร** ให้สิทธิ์ได้เฉพาะขอบเขตที่ตนรับผิดชอบและไม่เกินสิทธิ์ที่ตนมี ไม่สร้างผู้ดูแลส่วนกลางหรือเปิด/ปิดบัญชีส่วนกลางเอง
- ผู้ที่มีสิทธิ์เพิ่มทะเบียนแต่ไม่ได้ดูแลข้อมูลหลัก ต้องเลือกชนิดอุปกรณ์จากบัญชีที่กำหนด การเพิ่มเลขทะเบียนเดิมใช้หน้านำเข้าหรือผู้ดูแลทะเบียน
- รายชื่อบุคลากรในข้อมูลหลักเป็นรายชื่อผู้ปฏิบัติงาน ไม่ใช่บัญชีล็อกอิน การเลือกชื่อบุคลากรไม่ได้ให้สิทธิ์ผู้ใช้งานเพิ่ม
- หน้าที่ปัจจุบันเลือกได้เฉพาะบทบาทที่ผู้ใช้ได้รับสิทธิ์ เซิร์ฟเวอร์ไม่เชื่อข้อความ `actor` ที่ส่งมาเอง และตรวจองค์กร/สาขาของ ID ครุภัณฑ์ ใบงาน งาน PM ไฟล์แนบ และชุดนำเข้าทุกครั้ง
- แจ้งเตือนอ่านแยกตามผู้ใช้ หน้าที่ และขอบเขตองค์กร งานขององค์กรอื่นไม่รวมเข้ารายการหรือจำนวนแจ้งเตือน

ใช้ cookie session แบบ HttpOnly/SameSite และ CSRF token สำหรับแก้ข้อมูล รหัสผ่านเก็บด้วย PBKDF2 พร้อม salt ไม่เก็บรหัสผ่านตรง ๆ เซสชันมีอายุ 8 ชั่วโมง การเปลี่ยนรหัสผ่านหรือแก้สิทธิ์ผู้ใช้ยกเลิกเซสชันเดิม การใช้งานผ่านเครือข่ายภายนอกให้ใช้ HTTPS และตั้ง `PUBLIC_BASE_URL` เป็น HTTPS เพื่อส่ง cookie แบบ Secure

ลิงก์ Smart QR ที่มี token ยังเปิดข้อมูลสาธารณะเฉพาะรายการและแจ้งซ่อมได้ตามการออกแบบเดิม ไม่เปิดทะเบียนต้นทาง การเงินทั้งหมด หรือไฟล์แนบขององค์กรผ่านลิงก์นั้น

## อ่านคู่มือและจัดบัญชีอุปกรณ์

เปิด **ตั้งค่า → บัญชีอุปกรณ์และนำเข้าทะเบียน**:

1. **บัญชีอุปกรณ์** ค้นชื่อ รหัส หรือกรองหมวด ชนิดที่พร้อมใช้อ้างอิงรหัส 3 ชุด และระบบออกเลขรันเมื่อสร้างครุภัณฑ์จริง
2. **รายการตาม PDF** ดูรายการและรหัสตามพิมพ์ พร้อมเลขหน้า ผู้ดูแลเชื่อมรายการเหล่านี้เข้ารหัสใช้งานได้โดยยืนยันความหมายก่อน ไม่แปลงตัวเลขจากตารางให้เอง
3. **หลักเกณฑ์** แสดงความหมายเลข 4 ชุดและข้อความจากคู่มือ ผู้ดูแลแก้ข้อความฉบับใช้งานได้ โดยเก็บข้อความต้นฉบับและ SHA-256 เดิมไว้

การผูกค่าเสื่อมใช้หลักเกณฑ์ที่หน่วยงานตรวจแล้ว ระบบไม่ถืออัตราตัวอย่าง DEMO เป็นอัตราราชการจริง และไม่เดารอบรายเดือน/รายปีจากหัวข้อกว้าง ๆ ว่า “มูลค่าเสื่อม”

## นำเข้า ZIP / Excel ด้วยตนเอง

เปิดแท็บ **นำเข้าทะเบียน ZIP / Excel** หรือกดปุ่มนำเข้าที่หน้าทะเบียน:

1. เลือกองค์กรและสาขาเจ้าของทะเบียนก่อนเลือกไฟล์ รองรับ ZIP ที่มี XLS/XLSX หรือไฟล์ XLS/XLSX เดี่ยว ขนาดไฟล์อัปโหลดไม่เกิน 24 MB
2. หากต้นฉบับเป็น `.rar` ให้แตกไฟล์บนเครื่องแล้วบีบอัดโฟลเดอร์ Excel เป็น `.zip` ก่อน ไม่ต้องแปลงเนื้อหา Excel เป็น CSV
3. กด **ตรวจตัวอย่างและหัวคอลัมน์** ระบบอ่านทุก worksheet ที่ตรวจพบหัวตาราง ไม่เพิ่มทะเบียนในขั้นนี้ แผ่นที่ไม่พบหัวข้อมูลจะมีคำเตือนเพื่อให้ตรวจ ไม่หายไปเงียบ ๆ
4. ตรวจองค์กรเจ้าของ จำนวนรายการ หมวดต่อแผ่น หัวคอลัมน์ทั้งหมด และตัวอย่างแถว ช่องที่ระบบยังไม่รู้จักเก็บเป็นข้อมูลต้นฉบับเพิ่มเติมโดยไม่ทิ้ง
5. เลขว่าง เลขซ้ำ และเลขนอกรูปแบบแสดงจำนวนให้ตรวจ เก็บรายการและเลขเดิมไว้พร้อมสถานะต้องตรวจทาน ไม่เติมเลขทดแทน ไม่ตัดหลัก และไม่เปลี่ยนเลขให้อัตโนมัติ
6. เลือกหมวดให้ครบทุกแผ่น เลือกยืนยันแล้วกด **นำเข้าข้อมูลจริงตามต้นฉบับ** ระบบสำรองฐานก่อนนำเข้าและบันทึกชุดนำเข้าเป็นธุรกรรมเดียว ถ้าผิดพลาดย้อนทั้งชุด ถ้าเครือข่ายขาดให้ยืนยัน job เดิมได้โดยไม่เพิ่มซ้ำ
7. เมื่อเสร็จ เปิดทะเบียนหรือใบทะเบียนคุม แล้วขยาย **ข้อมูลทุกหัวข้อตามไฟล์นำเข้า** เพื่อดูหัวข้อและค่าต้นทางทุกช่อง

ชุดที่เคยนำเข้าสำเร็จแล้วตรวจจาก SHA-256 ร่วมกับองค์กรและสาขาเพื่อไม่เพิ่มซ้ำ เปลี่ยนชื่อไฟล์อย่างเดียวไม่ทำให้ข้อมูลเข้าอีกรอบ หากนำไฟล์เนื้อหาใหม่ที่มีเลขเดิมเข้ามา ระบบเก็บเป็นอีกรายการพร้อมธงเลขซ้ำเพื่อให้ตรวจ ไม่ถือว่าเป็นการแก้ไขทะเบียนเดิมโดยอัตโนมัติ

ZIP เมื่อแตกไม่เกิน 256 MB รวมไม่เกิน 100 workbook และ 300,000 แถวต่อชุด ตรวจเส้นทางไฟล์ ไฟล์เชื่อมโยง การเข้ารหัส ZIP และขนาดก่อนอ่าน ไม่รัน macro หรือสูตร Excel สูตรและค่าต้นทางที่อ่านได้เก็บไว้เป็นข้อมูลต้นฉบับ

## หัวข้อทะเบียนจริงที่รองรับ

ชุดต้นแบบ 19 ไฟล์มี 31 หัวข้อ ได้แก่ ลำดับ สถานะครุภัณฑ์ บำรุงรักษา เลขครุภัณฑ์ เลขเดิม กลุ่ม ประเภท ชนิด รายละเอียด ปีงบ GFMIS PO ใบส่งของ รุ่น Serial แบบ/ลักษณะ ฝ่าย/สายรับผิดชอบ หน่วยงาน/กอง วันส่งมอบ วันได้มา วิธีได้มา อายุใช้งาน ราคาทุน มูลค่าเสื่อม ค่าเสื่อมสะสม มูลค่าคงเหลือ วันที่ประเมิน วันคงเหลือ เช่า/ยืม ราคาเช่า/ยืม และวันที่แก้ไขล่าสุด

เก็บหัวข้อทั้งหมดใน `source_columns` และค่าทุกช่องใน `source_row_records` พร้อมองค์กร แผ่นงาน และเลขแถว นำค่าที่มีช่องทะเบียนไปเชื่อมเป็นทะเบียน ข้อมูลการได้มา และยอดค่าเสื่อมต้นทาง คอลัมน์เพิ่มเติมและชื่อหัวที่ซ้ำยังคงอยู่โดยมีลำดับแยก ไม่ทิ้งเพียงเพราะยังไม่มีช่องหน้าจอเฉพาะ

เลขสามชุดแรกที่แยกได้ตรงรูปแบบจึงจะบันทึกเป็นรหัสจำแนก ไม่ผูกกับชื่อใน PDF แบบคลุมเครือ ยอดค่าเสื่อมสะสมและมูลค่าคงเหลือใช้ค่าจากต้นฉบับ ไม่คำนวณทับ คำว่า “มูลค่าเสื่อม” เก็บเป็นยอดต้นทางทั่วไป หากไม่ได้ระบุงวดจะไม่อ้างว่าเป็นค่าเสื่อมรายเดือนหรือรายปี

## สำรองและกู้บัญชีผู้ดูแล

การสำรองฐานทั้งระบบรวมข้อมูลและรหัสผ่านที่ hash แล้วของทุกองค์กร จึงจำกัดให้ผู้ดูแลระบบส่วนกลาง ส่วนไฟล์ข้อมูลจริงและชุดสำรองไม่อยู่ใน GitHub การนำเข้าเก็บต้นฉบับไว้ในพื้นที่ `.sources` ที่รวมเข้าชุดสำรองเดิมแล้ว งานที่ยังตรวจตัวอย่างอยู่เก็บแยกใน `.imports`

เมื่อเข้าคอนโซลเครื่องที่เก็บฐานได้ ใช้คำสั่งต่อไปนี้ โดยรหัสผ่านจะถามใน Terminal ไม่รับเป็น argument:

```powershell
.\.venv\Scripts\python.exe scripts/manage-users.py create-admin --db "$env:ASSET_DB_PATH" --username admin --name "ผู้ดูแลระบบ"
.\.venv\Scripts\python.exe scripts/manage-users.py reset-password --db "$env:ASSET_DB_PATH" --username admin
```

ใช้ชื่อผู้ใช้จริงที่ต้องการและ path ฐานเดิม สคริปต์สำรองก่อนแก้และยกเลิกเซสชันเดิมเมื่อรีเซ็ตรหัสผ่าน ไม่เปลี่ยนสิทธิ์ของผู้ใช้จากการรีเซ็ตรหัสผ่าน
